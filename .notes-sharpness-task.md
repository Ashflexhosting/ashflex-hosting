# Screenshot Sharpness Fix — task notes

## Problem
User reports portfolio page + portfolio detail page screenshots look blurred.

## Diagnosis (debug agent, high confidence)
Sources are too narrow for rendered sizes on 2x DPR screens:
- fullpage WebPs: 380–760px wide (marveltex 380x902, shutterspeed 570x3384, bcfna 734x3154, aerolead/beccamiche 760px wide)
- Portfolio card CSS width ~513px (3 cols in 1200px container): DPR2 needs ~1026px → browser upscales = blur
- Detail hero card is ~2/3 of 1200px container ≈ 800px CSS → needs ~1600px
- Inner gallery tiles (portfolio-*-inner) are 893x768 → okay for tiles but soft at full lightbox zoom
- Hover: `.portfolio-card:hover .portfolio-image { transform: scale(1.02) }` rasterizes at lower res — soften
- Lightbox zoom mode scales img — magnifies blur

## Fix plan (decided approach: AI-upscale sources 2x, keep layout)
1. In /home/ubuntu/webdev-static-assets: for each fullpage webp, upscale width x2 (380→760, 570→1140, 734→1468, 760→1520) using high-quality Lanczos upscaling (Pillow LANCZOS), save as high-quality WebP (q=88)
2. Upload upscaled versions via `manus-upload-file --webdev` → new storage URLs
3. In client/src/data/portfolio.ts, replace image URLs for affected projects:
   - marveltex (marveltex-fullpage.webp)
   - shutterspeed (shutterspeed-fullpage.webp)
   - bcfna (bcfna-fullpage.webp; note afnaf card also uses bcfna-fullpage webp?)
   - aerolead, beccamiche (760 → 1520)
4. Remove/neutralize `.portfolio-card:hover .portfolio-image { transform: scale(1.02) }` in index.css (change to translateY/shadow only or keep but drop scale)
5. Check CaseStudies.tsx images using fullpage captures too; update URLs there if present
6. Run pnpm test (expect 24/24), screenshot /portfolio + /portfolio/3, checkpoint + auto-publish
