## Investigation round 2 (user: problem started with dark/light switcher; suggests removing menu bg image)
KEY INSIGHT found in Navbar.tsx:
- Line 293: mobile toggle row uses `flex items-center gap-1.5 lg:hidden` with the theme button THEN the hamburger. But the NAV BAR ITSELF (line 148-155): when NOT scrolled it is `bg-transparent`. When scrolled: `bg-white/80 ... dark:bg-[#071633]/85`.
- CRITICAL: `@custom-variant dark (&:is(.dark *));` (index.css line 4) — the dark variant applies to .dark * (descendants). The ThemeProvider toggles class `.dark` on <html>. On mobile the nav bar when not scrolled is transparent; toggle buttons are `text-white` when not scrolled.
- When user switches to DARK theme: body becomes dark (--background dark navy), text becomes light. BUT the mobile hamburger button when NOT scrolled stays `text-white` — fine over dark bg. When scrolled on dark theme, nav becomes `dark:bg-[#071633]/85` with `hover:bg-muted` (dark muted oklch 0.24) and `text-foreground/70` (light text) — still fine.
- HOWEVER the mobile MENU PANEL background: the spotlight JPG + warm glow overlay (lines 340-353) — if the image fails to load or the warm overlay + theme CSS clash, the white text could become invisible. ALSO: panel header border `border-amber-400/25`, links white text.
- SUSPECT: When `.dark` is set on <html>, the `.dark` prefix on nav classes triggers via `(.dark *)`. But the panel is fixed-position at z-65 inside <nav> — fine.
- Another real candidate: `backdrop-blur-[3px]` on the swipe container combined with the bg image can make iOS Safari treat taps as hover gestures or delay clicks (blur on scrolling div). On iOS, `backdrop-blur` + `-webkit-overflow-scrolling` sometimes makes first tap trigger hover, second tap = click.
DECISION (per user): (1) REMOVE the background image + glow overlay from the mobile panel — replace with a clean solid navy gradient bg (dark bg-gradient-brand with noise); (2) remove backdrop-blur on swipe container; (3) keep white/amber link styling; (4) simplify theme toggle: keep it outside menu; ensure toggle's tap doesn't propagate (it's separate button, fine).
ALSO add: `fast-tap` — on iOS, add `touch-action: manipulation` to interactive elements so double-tap zoom doesn't interfere with taps.
